```python
"""RULING-10 instrument: READ-ONLY measurement of the local memory ledger (sqlite, mode=ro; never :18500)."""
import json, sqlite3, sys, collections
DEFAULTS = {"decision": 0.9, "gotcha": 0.8, "ongoing": 0.7, "uncertainty": 0.6, "fact": 0.5}
con = sqlite3.connect(f"file:{sys.argv[1]}?mode=ro", uri=True)
rows = {mid: json.loads(meta) for mid, meta in con.execute("select memory_id, metadata from memories")}
kinds = collections.Counter(m.get("kind") for m in rows.values())
trust = collections.Counter((m.get("source") or {}).get("trust") for m in rows.values())
src_kind = collections.Counter((m.get("source") or {}).get("kind") for m in rows.values())
with_imp = {k: m for k, m in rows.items() if "importance" in m}
overrides = {k: m for k, m in with_imp.items() if m["importance"] != DEFAULTS.get(m.get("kind") or "fact")}
shapes = collections.Counter((m.get("kind"), m["importance"], (m.get("source") or {}).get("trust")) for m in overrides.values())
sup = {k: m for k, m in rows.items() if m.get("supersedes")}
pairs = collections.Counter(); missing = 0
for k, m in sup.items():
    pred = rows.get(m["supersedes"])
    if pred is None: missing += 1; continue
    pairs[((pred.get("source") or {}).get("trust") or "none", (m.get("source") or {}).get("trust") or "none")] += 1
cross = sum(v for (a, b), v in pairs.items() if a != b and "none" not in (a, b))
print(f"rows={len(rows)} kinds={dict(kinds)}\ntrust={dict(trust)} source.kind={dict(src_kind)}")
print(f"rows_with_importance_meta={len(with_imp)} overrides={len(overrides)} shapes={dict(shapes)}")
print(f"supersedes={len(sup)} pred_missing={missing} pairs={dict(pairs)} cross_trust={cross}")
print(f"created_at={sum('created_at' in m for m in rows.values())} valid_until={sum('valid_until' in m for m in rows.values())} superseded_by={sum('superseded_by' in m for m in rows.values())}")
```

## 1. 67a U1 sub-fork — RECOMMEND (b): drop the `importance` parameter AND the column; re-home the kind vocabulary on a `Literal` in `memory/backend.py`

**The question the lead asked is the whole argument: what is a writer agent told when it passes `importance=` and nothing ever reads it?** Under (a) the served parameter description says "importance override … omit to take the by-kind default", the call returns an id, and nothing anywhere — not the render, not the ranking (`_row_score` is RRF only), not any future consumer — reads the number. The writer acted on the response without checking and is wrong in a way the response did not name: it believes its note will weigh more. That is the hard definition's failure, on the WRITE side, on every call that passes the parameter (17 real writers did). Leg 2 is worse: a stored field nothing reads has NO forgery state — stale, empty, wrong, partial all serve identical bytes — so (a) cannot even be pinned; it is "a diagnosis without an instrument" by construction. Keeping it "for a future ranker" is the hazard in a different coat: the day something silently starts reading it, served results change with no provenance a consumer can see. If decay/weighting is ever adopted (the not-adopted list names the trigger), importance comes back DELIBERATELY, with a render that states it — never resurrected from a dormant column.

- **(b), as a requirement with its riders in the same bullet:** remove the tool parameter, `MemoryBackend.remember(importance=)`, `_resolve_importance`/`_default_importance`/the floor-ceiling constants, `IMPORTANCE_DEFAULTS_BY_KIND` and `REINFORCEMENT_STEP` (with D1), `RecalledMemory.importance`, `_build_content(importance=)`, `_row_to_recalled`'s read, `_COL_IMPORTANCE`'s DDL (`REMOVE FIELD` per the store reference §1, with the dirty-store verify D3 already owes), the fake, the `TestImportance*`/`REQUIRED_REINFORCEMENT_STEP`/reinforce pins (removed-behaviour inventory, one row each, fate `dropped-deliberately: no consumer reads it` — the 17 writer intents are not lost in any consumer-visible way: emphasis belongs in the note TEXT, which every reader reads). **And pin it like this:** (i) the ledger's 284 legacy rows keep `importance` in their JSON metadata forever — replay IGNORES the key: a fixture ledger row carrying `importance: 0.95` restores and recalls byte-identically to one without (a legacy-row fixture, not a fresh one — the fixture-guarantees-the-condition law); (ii) the recall render carries no `importance` token for any row (the U1 pin); (iii) `lore_remember` with `importance=` is REFUSED BY NAME with the reason — see the transition rider.
- **Transition rider (the writer's teaching):** probe at build what this MCP layer serves for an unknown parameter. If the served error is generic ("unexpected argument"), keep `importance` for one cycle as a REFUSING parameter whose description and error both say *"retired (67a): nothing ranks or renders it — put emphasis in the note text"*; delete it on the trigger "zero refusals in the trace table over 30 days". A parameter accepted-and-ignored (`metadata`'s DEPRECATED pattern) is the (a) lie and is not acceptable here; a loud refusal with the remedy is honest and costs the writer one edit (the operator's "refusal causes work-around" concern is about A1, where the work-around corrupts data; here the work-around IS the remedy).
- **Re-home the kind vocabulary (either option):** `MemoryKind = Literal["fact", "decision", "gotcha", "uncertainty", "ongoing"]` in `memory/backend.py` (the Protocol module, beside `TrustLevel` — same idiom, ONE owner), `VALID_MEMORY_KINDS = frozenset(get_args(MemoryKind))` DERIVED from it; `server._VALID_MEMORY_KINDS` imports it, never re-spells. ## 2. 67c A1 — the combined form (mint + allow-and-name + Fable minus refusal): what composes, what contradicts, the form, the forgery each piece closes, the fixture matrix

**Compose / contradict, stated plainly:**
- Opus's **allow-and-name** is the spine; everything else attaches to it or is redundant with it.
- Sonnet's **system-minted `uncertainty` note** CONTRADICTS the spine as a system action: a supersede CLOSES the predecessor; an uncertainty note asserts two LIVE notes disagree. Doing both is a contradiction in the data, and as a mere record of the crossing it DUPLICATES what is already stored and derivable at read time (`successor.supersedes` → predecessor's `trust` ≠ successor's `trust`). A stored copy of a derivable fact drifts (ONE source of truth). **What survives of Sonnet's form is the WRITER's alternative**: a writer who is not sure the authoritative note is wrong should not supersede at all — it saves `kind=uncertainty` naming the old note (both stay live). That path exists today; the combined form NAMES it in the response of every downgrade crossing and in the tool description, instead of minting it behind the writer's back.
- Fable's **"trust=authoritative REQUIRES source_ref"** IS a refusal in disguise — it refuses the adjective without the pointer — and it pushes writers to OMIT (save a sourced-in-fact note as experiential because the ref is not to hand) or to invent a ref (an over-claim of a worse kind: a pointer to nothing). Both corrupt the trust field the reader acts on. The idea underneath is right — trust should come from how a note entered, not the writer's adjective — and it survives as a RENDER DISTINCTION, not a gate: `MemorySource.ref` already exists and is unsettable at the tool (read); expose it as `source_ref`, and render `trust: authoritative (source: <ref>)` vs `trust: authoritative (unsourced — the writer's assertion)`. The reader sees the bound; the writer gains an incentive, not a wall. Fable's **teaching text** (name the old note's trust/ref and the two remedies) survives verbatim, as the response's guidance lines.
- Nothing else contradicts: the render provenance (67b, prerequisite) is what makes the naming readable later; both-trusts-both-sides fixtures are common to all three.

**The combined form (67c), each requirement with its rider:**
1. **A cross-trust supersede is ALLOWED and the response NAMES it**, appended after the id line (the existing contract: first line = the id, later lines = guidance, exactly as the digest warning does — so the "id ALONE" pin changes to "first line is the id", a named contract change for the operator): downgrade (authoritative ← experiential): *"superseded AUTHORITATIVE note <old-id> (source: <ref> | unsourced) with an EXPERIENTIAL note. If you were not certain the old note is wrong, the honest shape is kind=uncertainty naming <old-id> (both stay live); you can still save that now."* Upgrade (experiential ← authoritative): one line naming the crossing, no teaching. Same-trust: no line. **Pin:** the 2×2 trust matrix (× `source_ref` present/absent on the predecessor) — response bytes differ on exactly the two crossing cells; mutation: a build that names the crossing from the SUCCESSOR's trust alone (never reads the predecessor) fails the matrix.
2. **The render derives the crossing at READ time from the stored chain** — `supersedes <old-id> (authoritative, unsourced)` read from the predecessor row live (the X2 chain read), never from a copy stored at write time. Forgery closed: a predecessor later retired/deleted (X5's 26 legacy predecessors) renders *"predecessor <id>: not found"* — a named bound, never a silent omission or a stale copy. **Pin:** delete the predecessor row behind a rendered chain ⇒ the bound line appears.
3. **`source_ref` exposed, optional, rendered; no requirement.** When the ref is a lore chunk key it is drift-marked by the SAME oracle `refs` already use (`_resolve_existing_chunks`, the existing drift marker) — so "a ref to nothing" is visible; a URL/doc anchor stays unverified and is rendered as given (stated bound in the render). Forgery closed: a sourced-looking authoritative note whose source no longer exists renders drifted. **Pin:** matrix × {chunk-key ref, foreign ref, none}; mutation: drop the drift check for `source_ref` ⇒ RED.
4. **The tool description teaches the vocabulary**: `trust=authoritative` means "a spec/doc says so — give `source_ref` so readers can check"; `kind=uncertainty` is the shape for "I doubt an existing note but cannot prove it". Derived prose where it names sets (kinds, trusts), per §1.
5. **No system-minted rows, no refusal, no new field beyond `source_ref`.** Audit of the crossing is the chain itself plus the existing `audit_store` plan the guarded close already carries (#441, read) — nothing new to invent.

**Forgery states, per piece (Leg 2, dependency × verb):** (1) store × partial — close landed, create did not: impossible by the existing ONE-transaction design (read; keep its pin); response × stale — a response composed from the request's trust instead of the stored predecessor's: killed by the matrix. (2) chain × stale/deleted predecessor: the not-found bound. (3) ref × drift: the oracle. The one state no piece closes: a writer asserting `authoritative` with a plausible but false foreign ref — honest-developer threat model, stated in the design; the render's "(source: …)" at least makes the claim checkable.

**Fixture matrix (both trusts on both sides, plus the real populations):** predecessor trust ∈ {authoritative, experiential, **none** (10 legacy rows exist)} × successor trust ∈ {authoritative, experiential} × predecessor `source_ref` ∈ {chunk key, foreign, absent} × predecessor state ∈ {live, retired, deleted}. Required cells: the 2×2 core (response naming), the two `none` cells (render "trust unrecorded (pre-v2 row)" — never "experiential" by default on the RENDER even though replay defaults it), the deleted-predecessor cell (bound line), the drifted-ref cell. Fixture law: vary the branch value — today's `TestSupersession` is kind="fact", default trust both sides (Fable's code fact), the monoculture that let the silent crossing live.
