## FORK-R8-1 — `red_nodeids` on the FILE entry (author's choice) vs on the BOUND: **CONFIRM the file entry, with one consistency rider.**
- The registry's own grammar decides it: a `PendingBound` groups files that share ONE owner and ONE trigger (its docstring: "the owner and the trigger are the same fact eleven times over"); a `PendingFile` carries the CLAIMS about one file (`missing_symbols`, `unsymboled_codes`, and `admits()`). A node id is a claim about one file — it carries its path — so it belongs beside the file's other claims as the third claim kind. That is also what keeps the existing refusal honest: `--verify-registry` refuses a file entry "with no claim at all" (file-only matching waves through a new defect); with ids on the bound, a pytest-only file would need either a claim-less `PendingFile` (refused) or no entry (then the bound's `files:` no longer names what it covers). §R3.7(c)'s "on the bound" was round 3 writing before the schema was read; ruling 6 already said "`red_nodeids`-only `PendingFile`", and the F6 contract pins that shape (per-node partition for a node-listed file; no typecheck self-destruct for a pytest-only file; refuse `red_nodeids: []` with nothing else).
- Rider — the one property per-file placement needs that the F6 contract does not pin: **an id listed under a file entry whose path prefix (before `::`) is a DIFFERENT file is a registry error, refused by `--verify-registry`.** Without it a misfiled id still adjudicates the red (matching is by full id) while the `files:` list lies about which files the bound covers, and the misfiled file's own partition stays file-level. One validator line + one test; routed to the servicing author (R23) in the commit that registers `packet66_entry.yaml` after F6 lands — not a new round. The filled entry (302 ids / 27 files) is consistent by construction today (each id sits under its own path, read); the rider keeps it so.
- Leg 1 / Leg 2 (R17, the gate's served surface is the currency verdict): the verdict answers *"which reds have an owner and a trigger?"*; per-file ids with the stale and self-destruct legs mean the answer cannot drift — a renamed node reds the gate, a healed node reds the gate. Placement does not change the legs; the rider closes the one forgery (a misfiled id) the legs cannot see.
