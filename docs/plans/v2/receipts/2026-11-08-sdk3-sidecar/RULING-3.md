The lead's four constraints are the right riders. Three additions make "listed" and "does not weaken" CHECKABLE BY CONSTRUCTION rather than by an auditor reading diffs — the DUAL law (a diff that deletes tests carries a removed-behaviour inventory) and the LEVER (a law an agent can ask itself mid-task).

- **Rider 1 — the builder's test edits land in a SEPARATE commit from the production change, and the list is verified by a both-ways diff, not read.** Run the PRE-edit test tree against the build → red set R1; run the POST-edit tree → R2. Then: (a) every node in R1∖R2 is touched by a LISTED edit (else an unlisted edit made a red disappear — NO-GO, mechanically); (b) every listed edit's node is in R1 (else the edit had no SDK-2.0 cause — it is a weakening with no reason, or an unnecessary churn — adjudicate); (c) R2 ∖ R1 = ∅ (test edits never add reds). This is MP-C's both-ways form pointed at the builder's own edits; the cold audit's contract-blind pass then reads only the (a)/(b) exceptions. *Ask yourself: "if a test edit silently hid a product red, would step N+1 still print green?" — with one combined commit, yes.*
- **Rider 2 — "encodes SDK 2.0" is a VERDICT with an inventory row, never a label.** A REMOVED or rewritten test names the behaviour it certified at HEAD and exactly one fate: `carried-by <new pin node id>` · `retired-with drop-list row #N` (the SDK-2.0 shape no longer exists) · `old-bug (#…)`. "Encodes SDK 2.0" with no row is the same move as "flaky": it can be said of anything red. For MP-C's amended property this means the escape clause is bounded by the inventory, and the am-37 adjudication table is the home (R15 already made those rows contract surface).
- **Rider 3 — F-a as SDK-3-only fakes reddens HEAD until the build lands; those reds are REGISTERED (F6 `red_nodeids`, owner: the SDK3 builder, trigger: the build commit), else the currency gate reads RED_ORPHANED for the whole interim.** Each of those nodes also appears in Rider 1's R1 by construction (they are red before the build), so they cannot be mistaken for a builder weakening.
