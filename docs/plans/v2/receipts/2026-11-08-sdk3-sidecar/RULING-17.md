## (1) Reachability, per door — by CONSTRUCTION this time, not by clock

- **Every production write is held to the type.** All three tables are SCHEMAFULL and the three stamp columns are `datetime` / `option<datetime>`; §1.4 (measured, re-confirmed on 3.3.5): *new writes are held to the new type*, so a `CREATE`/`UPDATE` carrying a string, number, bool or duration into these columns is REJECTED by coercion. The code writes only `time::now()` (task) and Python `datetime` (finding, message); no door passes a caller-supplied stamp.
- **No pre-schema era.** `git log -S` finds no commit in which any of these stamps was `string`, `any`, or sat on a SCHEMALESS table. (The one SCHEMALESS table is `name`.)
- **Export/import preserves type.** A `surreal export` renders datetimes as typed `d'…'` literals and carries the SCHEMAFULL DDL in its preamble; `restore_prod_dump.py` reproduces a dirty stamp iff the source had one (§6.7's non-atomicity is about partial loads, not retyping). The `/backups/lore` copies are file-level.
- **The ONE door is an admin DDL retype** — exactly the recipe the 66d fixture needs to construct the state: retype the column to `any`/`string`, write, retype back; §1.4 says the engine never re-validates the row. That is a MIGRATION in our own hands (#107's door class), never an agent's call, never the fleet's traffic.
- **One sub-case I did not construct and name as such:** whether `option<datetime>` admits an explicit `NULL` (SurrealDB distinguishes NONE from NULL; `option<T>` is `T | NONE`). No production path writes NULL there; the follow-up's first probe is one statement.

So the servicer's "legacy row whose stamp is a STRING" is a row some human retyped a column under. Reachability: unreachable through every production write; reachable through one operator action that §1.4 already marks *"migrate rows separately"*.

## (2) The fix — NOT a per-call check in the helper. Pin the miss now; the closing instrument belongs at the migration chokepoint.

Why not the helper: a per-leg `count()` of non-datetime stamps is a TableScan per leg per rollup call (no index can answer a type test), paid on every fleet catch-up to detect a state only an admin DDL can produce — the honest-developer threat model (A GATE NEEDS A THREAT MODEL) puts the door at the migration, so the guard goes where the door is. And the right POSTURE on detection is R34's: refuse loudly until rows are migrated — a boot-time fact, not a per-call one.
