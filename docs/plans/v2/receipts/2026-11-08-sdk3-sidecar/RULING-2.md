## 1. R18 — verdict: **CONFIRM the direction; AMEND four clauses** (none reverses an operator ruling; R11 is honoured more literally, not less)

R18's diagnosis is right and measured: `loresigil.backoff` drives `wait_random_exponential` through a fake `RetryCallState` (`_RETRY_OBJECT = AsyncRetrying()` built solely "to satisfy that constructor", its own comment) while every loop stays hand-written; and R12-F22's name-keyed recorder forced a `_wait` that peeks at `stop`, which forced MP-B. Those are tests of the OLD implementation shaping production around the package — the spelling-check class in a new costume. Confirmed facts from the installed source: tenacity's `wait_random_exponential(multiplier=base, max=cap, exp_base=2)` IS HEAD's law to the character (`random.uniform(min, min(max, multiplier·exp_base^(n−1)))`); `stop_any(stop_after_attempt(64), stop_all(stop_after_delay(deadline), stop_after_attempt(5)))` IS HEAD's give-up predicate; `retry_error_callback` is the native exhaustion seam (it REPLACES the `RetryError` raise — `_post_stop_check_actions` returns before `exc_check`); `sleep=` is an injectable constructor parameter; the wait is computed before the stop (so a draw on the exhausting attempt is native and harmless once nobody counts draws).

### A1 — `before_sleep`/`after` "hooks for logging": AMEND → **no per-attempt log in `retry_on_conflict`; the ONE exhaustion record lives in `retry_error_callback`.**
Reason: X22 (R4.8, preserved-with-pin) — one record per terminal disposition, nothing on a resolved conflict; HEAD's own comment: p50 is TWO attempts per mint at every N ≥ 8, "a line per retried attempt would be a log storm in production". A `before_sleep` logger (even `before_sleep_log(logger, DEBUG)`) re-introduces exactly that. The transactional per-attempt `_log_rollback` already lives in the attempt body, outside the driver — untouched. Rider: `test_a_conflict_that_resolves_returns_the_value_and_logs_nothing` and `…logs_only_the_last_cause` stay as the pins; an `after`/`before_sleep` kwarg left unused is omitted, not passed as a no-op.

### A2 — "the 9 draw-count pins are RETIRED": AMEND → **retire the DRAW-COUNT assertions; CONVERT the recorder's CONTROL uses to the native `sleep=` seam. Never delete a control.**
Reason (read, not inferred): of the recorder's consumers in `test_retry_seam.py` (8 call sites by my grep at `05e17b4` — R12/R18 say 9; re-derive before retiring, a miscount here retires one pin blind or leaves one behind), several are CONTROLS, not implementation pins: the scout empty-claim pin asserts "an empty CAS result did NOT back off" (`assert not recorder.draws`), and the live 16-way idempotency family's premise is "the run actually RETRIED something (the shared-jitter recorder is consulted)". Delete those and T2 can pass VACUOUSLY on a build with no retry at all — the file's own warning, and Leg 2's exact false clear (a never-retrying driver serves byte-identical results on an uncontended run). Native form: the pins observe the SLEEP CALL — what the driver actually slept, through `sleep=` (inject a recording coroutine) or the one module-level `asyncio.sleep` patch — never a lore-named draw function. "did not back off" ⇒ the recorded sleeps are empty; "contention happened" ⇒ ≥1 sleep recorded (or the attempt body's own call counter > racers×rounds, which T2 already asserts). This also makes MP-B native for free: there is no "drawn" any more, only "slept".

### A3 — the behaviour pins as written ADMIT MP-B's survivor: AMEND → **add a distribution pin (full jitter reaches DOWN to zero).**
Reason: `wb_r11_sleepdrift` sleeps `window/2 + drawn/2` ∈ [w/2, w): inside R18's window bound, and decorrelated across racers — it passes "every slept delay ∈ [0, min(cap, base·2^(n−1)))" AND "≥8 racers do not sleep identical sequences". Equal-jitter-near-the-floor is the behaviour #102 ruled insufficient; the pin must see the LOWER tail. Form (contract author's call; the property is fixed): with `sleep=` recorded and the attempt index held constant, over ≥256 slept values the minimum lies below window/8 and the maximum above 7·window/8 (P(false red | correct) = 2·(7/8)^256 ≈ 3e-15; a `uniform(0, w/2)` build fails the upper tail, the `w/2 + d/2` build fails the lower tail, `wait_exponential_jitter` fails the window bound, `wait_exponential` fails decorrelation). Rider: the adversary's `wb_r11_sleepdrift` is the control build and must go RED. Mutation: swap the wait class → RED.

### A4 — the "no hand-rolling" principle needs a CHOKEPOINT after the shim dies (packet 68, and the `_txn`/scout half in 66): AMEND → **`loresigil.backoff` keeps ONE thing: a wait FACTORY, not a draw.**
Reason: R18 deletes the fake-`RetryCallState` shim (correct — it IS the "tenacity in name only" artefact) but then every retry site constructs `wait_random_exponential(multiplier=…, max=…)` itself. The per-site base/cap are configuration; **which tenacity wait class and exp_base** is POLICY, repeated at 7+ sites — a site that picks `wait_exponential_jitter` by mistake is #207 again, and `test_backoff_seam::TestEveryBackoffSharesTheOnePolicy` (which proves sharing by mutating the shared function) loses its chokepoint. Native and ONE-IMPLEMENTATION at once: `backoff.full_jitter(base_s, cap_s) -> wait_random_exponential(multiplier=base_s, max=cap_s, exp_base=BACKOFF_EXP_BASE)` (returns tenacity's own object; zero state) and `backoff.jittered_fixed(delay_s, width_s) -> wait_fixed(delay_s) + wait_random(0, width_s)` (tenacity's `wait_combine` via `+`) for the fixed-pause sites. Sharing pin: mutate the factory to return `wait_fixed(SENTINEL)` → every site's recorded sleep == SENTINEL (the existing pin's shape, re-keyed). The AST perimeter scan (no `**` by a variable outside the allowlist) stays as the deny-side instrument; `_POW_ALLOWLIST` empties per F-r5-1(b).

### R17 legs for R18 (retry is mostly unserved; these are its served bits)
- **Leg 1.** Served: `TxnContentionExhaustedError`'s text ("gave up after N attempts over Xs (retryable conflict); see server log") and the `store.retry.exhausted` record. Question answered: *"this statement/transaction did NOT commit, after N attempts"* — true by the at-most-once rule (a conflicted statement commits nothing; the transaction path rolled back). Question the agent asks: *"did my write land?"* → No. Scope diff: none — PROVIDED the callback carries `attempts` and the last cause (R18 says so) and the text keeps "retryable conflict" (the agent may retry; it is not outcome-unknown). F-b holds: a conflict is a server-ANSWERED definite failure, never "unknown".
- **Leg 2 (dependency = the driver × {never-retries, over-retries, correlated, un-awaited}).** (i) never retries ⇒ identical bytes on every uncontended run → T1/T2's contention PREMISE (A2 keeps the control). (ii) retries a non-signal (a transport-unknown) ⇒ serves "success" after a double apply → `test_a_single_statement_throw_is_not_retried` + F14 zero-retry pins (keep). (iii) correlated/equal jitter ⇒ identical bytes on every success; differs only in exhaustion RATE under contention → A3's distribution pin + decorrelation. (iv) **the un-awaited coroutine** (`retry_on_conflict(lambda: …)` handed to tenacity raw returns a coroutine OBJECT — truthy, nothing executed, no error): the deadliest false clear in this packet, found by the adversary as a reference bug. Pin it explicitly: `retry_on_conflict` RETURNS THE ATTEMPT'S VALUE (sentinel identity) for a lambda-shaped caller, and the scout LIVE/kill family stays as the live witness.
